# Architectural decisions

| # | Decision | Rationale | Alternatives considered |
|---|---|---|---|
| D1 | Use the problem summary in the master prompt as the working spec; `PS 01(1).pdf` was not found in the workspace, Desktop, Downloads or Documents. | Unblocks work; the prompt restates outputs, categories and evaluation priorities in detail. | Halt until PDF provided. **To do:** reconcile if the PDF is supplied. |
| D2 | Datasets: Scam Shield SMS (CC BY 4.0), Indian Scam SMS synthetic-audited (CC BY 4.0), UCI SMS Spam (CC BY 4.0, **ham only**); Scam Shield Test B for external evaluation only. All pinned by revision + SHA-256. | Real smishing reports (IMC 2025) + hard negatives (synthetic genuine service messages) + Hinglish/Hindi coverage. | Gated OTP dataset (requires login — skipped); Kaggle sets (need account); small 120-row Indian set (label noise: legit rows with "please act now"). |
| D3 | Drop UCI "spam" rows. | UCI spam mixes advertising with scams; the task is scam detection (Scam Shield made the same choice). | Keep as LOTTERY via keyword filter (would make labels depend on our own rules). |
| D4 | Category labels from source subtypes where available; documented keyword weak-labeller otherwise, flagged `category_source=weak_rule` and **excluded from category evaluation**. | IMC "others" bucket has no category; avoids grading the model against its own heuristics. | Manual labelling (not feasible in scope). |
| D5 | Group-aware split: near-duplicate clusters (char 3–5-gram cosine ≥ 0.8); Scam Shield's real val/test kept; train rows sharing a group with val/test dropped. | Prevents template leakage; audit shows 0% test rows ≥ 0.9 similar to train. | Random split (leaks templates). |
| D6 | Augment train only, class-balanced per mutation type; 6 of 11 mutation types held out from augmentation. | Prevents "obfuscated/Hinglish ⇒ scam" shortcuts; held-out types measure real generalisation of the normaliser. | Augment scams only (creates a fabricated shortcut). |
| D7 | Entity masking (xurlx, xphonex, xnumx…) for every source in the model text; structural evidence extracted before masking. | Scam Shield is pre-masked; masking everywhere removes a source-identity shortcut and keeps evidence for the rule engines. | Raw text (model would learn which dataset a message came from). |
| D8 | Semantic engine = word(1–2)+char_wb(2–5) TF-IDF + Logistic Regression (C=16). | Best LR on val AUC (0.9866); LinearSVM C=0.5 was 0.9872 (within 0.003) — LR kept for exact, faithful explanations and native probabilities. ComplementNB clearly worse (0.964). | Transformer (not attempted: large download + CPU latency; Priority 3 — see KNOWN_ISSUES). |
| D9 | Fusion = standardised LR over 47 features (semantic OOF logit, specialist OOF logit + applicability flag, 44 engine features); GroupKFold(5) OOF stacking with vectorisers refit per fold. | Avoids in-sample stacking leakage; linear meta-model gives exact per-feature contributions. | Gradient boosting (less transparent, marginal expected gain). |
| D10 | Calibration on val; sigmoid vs isotonic chosen by 2-fold CV Brier within val. | Enough val data (3,093) for isotonic; CV choice avoids picking on in-sample fit. | Calibrate on train OOF (distribution differs from val/test). |
| D11 | **Threshold fixed at 0.5** on calibrated probability. | Keeps verdict = more probable class, so confidence = calibrated P(verdict) ≥ 0.5. A FPR≤2 % rule picked 0.8 on val (FPR 1.85 %, recall 0.878 vs 0.928) but would show "SAFE" for messages with 75 % calibrated scam probability. FPR is reduced through the model (benign engine, specialist, official-domain list) instead. Sweep kept in `reports/training_report.json`. | Cost-sensitive threshold with recalibrated output. |
| D12 | Benign protection = rule templates + **transactional specialist** LR (trained only on messages with links/numbers/money/OTP/brands) + conflict detector. | Main model's decision boundary is dominated by chat-vs-scam; specialist focuses on hard negatives; conflicts keep "genuine shell + malicious ask" from being whitelisted. | Unconditional "OTP ⇒ SAFE" rule (explicitly forbidden, exploitable). |
| D13 | Category: multinomial LR on text + tactic tokens; OTHER fallback if max specific prob < τ (τ=0.5 tuned on val gold labels). | Avoids forcing unsupported specific categories. | Rules only (poor on unseen phrasing). |
| D14 | Explanations: fusion contributions (exact) + rule evidence labelled "supporting evidence"; template sentences; no LLM. | Faithful, offline, consistent with the prediction. | SHAP/LIME (slower, approximate). |
| D15 | Network guard patches `socket.connect` in the backend process (default on). | Turns the privacy claim into an enforced, testable property. | Documentation only. |
| D16 | FastAPI serves the built UI on the same loopback origin; routes available at `/` and `/api`. | One process, one port, no CORS in production; works with the Vite proxy in dev. | Separate static server. |
| D17 | Hand-built SVG charts; system fonts only. | No runtime third-party assets; small bundle (88 KB gz). | Recharts (≈ +100 KB gz). |
| D18 | Local official-domain list (`backend/data/official_domains.json`), manually compiled, includes RBI `.bank.in` domains. | Offline look-alike and brand-mismatch checks. | Downloaded PSL / reputation feeds (network at inference — forbidden). |

## Phase 2 — TEKMĒ

| # | Decision | Why | Alternatives rejected |
|---|---|---|---|
| D19 | Run inference **in the browser** (TypeScript port of preprocessing, rules, TF-IDF, fusion, calibration, category model and explainer), loading weights exported from the trained bundle. The Python engine stays the reference and the training/evaluation path. | User chose fully on-device iPhone use (Option A); a phone cannot reach the laptop's loopback server. One model, two verified implementations. | Pyodide (≈40 MB, sklearn pickle version mismatch); phone→laptop over Wi-Fi (not on-device); ONNX (TF-IDF analysers not supported faithfully). |
| D20 | Python regexes are **translated automatically** (`ml/export/pyregex.py`) into Unicode-correct JavaScript (Python's `\b \w \d \s $` semantics rebuilt with `\p{L}\p{N}` classes and lookarounds); data tables are exported, not retyped. | Hand-copying ~120 patterns invites silent drift; the translator fails loudly on anything it does not understand. | Manual port. |
| D21 | Parity is a **test**, not a claim: `ml/export/parity.py` records Python outputs for 5,072 messages; `frontend/tests/parity.test.ts` compares every field. | Result: verdict, category, tactics, signals, explanations and highlights identical on all 5,072; max probability difference 3.6e-6. | Spot checks. |
| D22 | Weights stored as **float32** in `model.bin` (6.6 MB, 3.5 MB gzip). | Halves download size; measured impact ≤ 3.6e-6 in probability, 4 messages differ in the 4th decimal of a displayed word weight. | float64 (≈ +5 MB). |
| D23 | Advanced features (forensics, conversation, counterfactuals, guidance, batch, library, redaction) are a **TypeScript analysis layer** over the engine with one typed contract (`analysis/analyze.ts`). They describe evidence and never change the model's verdict. | Works offline on the phone; one code path for every page. The Python API keeps the core `/predict` contract. | Re-implementing each feature in Python and TS. |
| D24 | Unfamiliar-message flag (cluster similarity or known-word coverage below the validation 5th percentile) is shown as a caveat; it turns a verdict into **UNCERTAIN only when confidence < 0.75** (and the borderline band 0.35–0.65 is always UNCERTAIN). | Measured: flags 10% of test and 19% of external Test B (detects shift) but accuracy flagged vs not is 94.3% vs 95.1% (test) — it barely predicts errors. | Treating every unfamiliar message as uncertain. |
| D25 | Scam-family clustering: k-means (k = 40) on the semantic TF-IDF space of the **training split**; families = clusters ≥ 80% scam with ≥ 30 members; examples redacted. Source comparison is labelled as a cross-source comparison (no per-message dates exist), not a timeline. | Honest Feature 3 and 9. | Inventing a trend over time. |
| D26 | iOS extension uses a **separate compact model** (word 1–2-gram TF-IDF, 6,000 features, Platt-calibrated) with ASCII-explicit regexes portable to ICU, and a junk threshold chosen for ≤ 1% validation FPR. | Extension memory limits and no Mac to validate a full Swift port; a filter that hides genuine SMS is harmful. Measured separately (reports/ios_compact_report.json). | Porting the full engine to Swift unverified; Core ML (no faithful TF-IDF conversion). |
| D27 | PWA via a hand-written service worker whose precache list is generated at build time; network-first for navigation, cache-first for hashed assets and the model; `/api` never cached. | No extra dependency; deterministic offline behaviour. | vite-plugin-pwa / Workbox. |
| D28 | Fonts Cinzel, Cormorant Garamond, Inter (OFL-1.1) bundled via @fontsource; theme set before first paint by an external `theme-init.js` (CSP forbids inline scripts). | Editorial look from the mockups with no font CDN; no theme flash. | Google Fonts CDN; inline script with `unsafe-inline`. |
| D29 | Athena artwork: user-supplied images generated for TEKMĒ (OpenAI image generation), used as-is; resized/compressed to WebP 720/1200/1774 px. No regeneration or third-party licence claimed. | User instruction; provenance recorded. | Cropping the mockups. |
